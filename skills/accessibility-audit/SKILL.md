# accessibility-audit

## Trigger
When UI must support WCAG, keyboard, screen readers or assistive technologies.

## Procedure
1. Identify target platforms, users and applicable standards.
2. Audit structure, focus, input labels, contrast and error recovery.
3. Run accessible test tools if available and mark manual checks pending.
4. Document failures with reproducible paths and severity.
5. Verify fixed issues without claiming unsupported compliance certification.

## Delegation policy
Use accessibility-engineer and frontend-engineer or mobile specialists.

## Done when
Actionable accessibility findings and tested remediations.
