# architecture-decision

## Trigger
For migrations, new framework choices or major architecture tradeoffs.

## Procedure
1. State measurable requirements, constraints and existing system facts.
2. Compare at least two feasible designs without vendor marketing claims.
3. Estimate operational costs, security, interoperability and migration steps.
4. Record chosen option, rejected options and future revisit triggers.
5. Obtain implementation approval for significant breaking changes.

## Delegation policy
Use architect and stack-specific read-only experts.

## Done when
Decision record grounded in repository evidence.
