# continuous-improvement

## Trigger
Use after repeated incidents, recurring code review findings, or a completed retrospective.

## Procedure
1. Identify a repeated pattern from concrete verified instances, not isolated speculation.
2. Propose a narrow rule, fixture or skill update with an acceptance check.
3. Redact personal data, credentials, proprietary code and customer-specific context.
4. Keep changes in version control for human review; never auto-commit learned rules.
5. Regression-test the new guidance against a known false-positive example.

## Delegation policy
Use reviewer and docs-writer; avoid silent self-modifying prompt files.

## Done when
A reviewed reusable rule or test and clearly stated supporting evidence.
