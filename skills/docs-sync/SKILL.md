# docs-sync

## Trigger
After behavior changes, interface changes or packaging updates.

## Procedure
1. Read actual implementation, tests and entry points before writing.
2. Update only relevant user-facing docs and API examples.
3. Check copy-pasteable commands and Windows/Linux compatibility.
4. Use realistic sample data without keys or personal information.
5. Flag features that are planned rather than available.
6. Mention known limitations and troubleshooting steps.

## Delegation policy
Use docs-writer; avoid parallel updates of the same README.

## Done when
Verified docs changes and explicit unverified examples.
