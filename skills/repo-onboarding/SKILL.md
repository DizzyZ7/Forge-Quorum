# repo-onboarding

## Trigger
For first contact with a large repo or a new contributor's first task.

## Procedure
1. Read root docs, build manifests, app entry points and test configuration.
2. Summarize runtime components, boundaries and data flow.
3. Find how to build, test, debug and deploy without guessing commands.
4. Identify risky/legacy sections and likely owners.
5. Locate existing patterns for the task at hand.
6. Keep findings linked to exact paths and symbols.

## Delegation policy
Use repo-explorer and optionally architect for complex monorepos; otherwise single-agent.

## Done when
Concise architecture map and verified setup commands, with unknowns clearly marked.
